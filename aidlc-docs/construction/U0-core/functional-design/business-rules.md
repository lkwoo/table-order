# Business Rules - U0 Core (공통)

**작성일**: 2026-08-31
**Unit**: U0 Core/Shared

전 Unit에 공통 적용되는 검증·제약·정책.

---

## 1. 공통 검증 규칙
| 규칙 | 내용 |
|------|------|
| 필수 필드 | Pydantic 스키마로 요청 단계 검증, 누락 시 422 |
| 가격 범위 | 1,000 ≤ price ≤ 100,000 (KRW, 정수) |
| 수량 범위 | 1 ≤ quantity ≤ 99 |
| 비밀번호(테이블) | 4~10자리 |
| 문자열 트림 | 이름/설명 등 앞뒤 공백 제거 |
| 이미지 URL | 형식 검사(선택 필드), 저장은 URL 문자열만 |

## 2. 트랜잭션 정책 (요구사항 4.4)
- 쓰기 서비스가 트랜잭션 경계 소유(Unit of Work). Repository는 트랜잭션 미개시.
- 다중 테이블 변경(세션 종료, 주문 삭제+총액)은 단일 트랜잭션.
- **이벤트 발행은 커밋 성공 후에만** 수행.

## 3. 인증/인가 공통 (가드)
- 관리자 엔드포인트: 유효 JWT 필수, 만료/서명 오류 시 401.
- 고객 엔드포인트: 유효 세션 토큰 필수, 만료 시 401.
- 매장 스코프 격리: 모든 조회/변경은 토큰의 store_id 범위로 제한(타 매장 접근 불가).

## 4. 세션 격리 (C12)
- 고객 주문 조회는 항상 현재 session_id로 필터. 서비스 레이어에서 강제.
- 만료(16h)/종료된 세션 토큰으로는 데이터 접근 불가.

## 5. 이벤트 종류 (EventBroker)
`OrderCreated`, `OrderStatusChanged`, `OrderDeleted`, `SessionEnded` — 각 이벤트는 `store_id`, 필요한 `table_id`/`session_id`/`order_id` 포함.

## 6. 시간/타임존
- 저장은 UTC. 표시 변환은 프론트 담당.
- 세션 만료: created_at + 16시간. 이력 보관: archived_at + 3개월 경과 시 정리 대상.

## 7. 오류 응답 표준
| 상황 | HTTP | 바디 |
|------|------|------|
| 검증 실패 | 422 | field errors |
| 인증 실패/만료 | 401 | code, message |
| 권한 없음(타 매장) | 403 | |
| 리소스 없음 | 404 | |
| 중복(테이블번호/username) | 409 | |
| 서버 오류 | 500 | 재시도 유도 |
