## 2. Persona → Story 매핑 (각 Persona가 사용하는 Stories)

### 고객 Persona (Multiple Segments)

#### 세그먼트별 사용 패턴

##### Segment A: 직관적 UI를 선호하는 일반 고객
- **필수 Stories**:
  - C1: 자동 로그인 (간편함)
  - C2: 초기 설정 (첫 로그인)
  - C3: 메뉴 리스트 (기본 기능)
  - C4: 상세 정보 (신중한 선택)
  - C6: 장바구니 추가 (주문 준비)
  - C7: 수량 조절 (정확성)
  - C9: 최종 확인 (실수 방지)
  - C10: 주문 생성 (확정)
  - C11: 주문 내역 조회 (진행 모니터링)

- **선택 Stories**:
  - C5: 메뉴 검색 (고급)
  - C8: 메뉴 제거 (실수 시)

- **간접 영향**:
  - A2, A3: 주문이 대시보드에 표시됨
  - A4: 상태 변경으로 C11 업데이트
  - A6: 주문 삭제 시 C11에서 제거

##### Segment B: 스마트폰 경험이 있는 일반인
- **필수 Stories**:
  - C1, C2, C3, C4, C6, C7, C9, C10, C11
  
- **선택 Stories**:
  - C5: 메뉴 검색 (유용)
  - C8: 메뉴 제거

##### Segment C: 기술에 능한 사용자
- **필수 Stories**:
  - C1, C2, C3, C6, C7, C9, C10, C11
  
- **선택 Stories**:
  - C4: 상세 정보 (필요시만)
  - C5: 메뉴 검색 (활용)
  - C8: 메뉴 제거

### 관리자 Persona

#### 관리자의 업무 흐름 (하루 일과)

**영업 시작 전**:
- A1: 로그인
- A5: 테이블 초기 설정 (필요시)
- A9: 메뉴 조회 (상태 확인)

**영업 중 (실시간 모니터링)**:
- A2: 실시간 주문 대시보드 (계속 모니터링)
- A3: 테이블 카드에서 상세 주문 보기 (주문 확인)
- A4: 주문 상태 변경 (대기중 → 준비중 → 완료)
- A6: 주문 삭제 (고객 실수 시)

**테이블 관리**:
- A7: 테이블 세션 종료 (이용 완료 후)
- A8: 과거 주문 이력 조회 (필요시)

**메뉴 관리 (비영업 시간)**:
- A10: 메뉴 등록 (신메뉴)
- A11: 메뉴 수정 (가격 변경 등)
- A12: 메뉴 삭제 (단종 상품)

## 3. Cross-Persona Stories (교차 영향 Stories)

### 고객 ↔ 관리자 상호작용이 있는 Stories

| Story | 고객 역할 | 관리자 역할 | 상호작용 |
|-------|----------|-----------|--------|
| **C2 ↔ A5** | 로그인 | 초기 설정 | 관리자 → 테이블 설정 후 고객이 로그인 가능 |
| **C10 ↔ A2** | 주문 생성 | 대시보드 감지 | 고객 → 주문 생성 → 관리자 대시보드에 실시간 표시 |
| **C10 ↔ A4** | 주문 중 | 상태 변경 | 관리자 → 상태 변경 → 고객 C11에서 SSE로 즉시 업데이트 |
| **C11 ↔ A4** | 조회 & 업데이트 | 상태 변경 | 관리자 → A4에서 상태 변경 → 고객 C11이 자동 업데이트 (SSE < 2초) |
| **C11 ↔ A6** | 주문 조회 | 주문 삭제 | 관리자 → A6에서 삭제 → 고객 C11에서 제거 (SSE) |
| **C11 ↔ A7** | 세션 주문 | 세션 종료 | 관리자 → A7 세션 종료 → 고객의 현재 주문이 과거로 이동 |
| **C3 ↔ A10,11,12** | 메뉴 조회 | 메뉴 관리 | 관리자 → CRUD → 고객 C3 메뉴 리스트 자동 업데이트 |

## 5. Dependency Map (Story 간 의존성)

### 선행 조건 (Prerequisite)

```
C1/C2 (로그인)
  ↓
C3/C4 (메뉴 조회)
  ↓
C6/C7/C8 (장바구니)
  ↓
C9 (최종 확인)
  ↓
C10 (주문 생성)
  ↓
C11 (주문 내역)
```

```
A1 (로그인)
  ↓
A5 (테이블 초기 설정)
  ↓
A2/A3 (주문 모니터링)
  ↓
A4 (상태 변경)
  ↓
A6/A7 (테이블 관리)
  ↓
A8 (이력 조회)
```

### 병렬 개발 가능 Stories

- **고객 인증**: C1, C2 (병렬, 순서 무관)
- **메뉴 탐색**: C3, C4, C5 (병렬 가능)
- **관리자 인증**: A1 (독립)
- **관리자 모니터링**: A2, A3, A4 (순차, 하지만 A2와 A3는 병렬 가능)
- **메뉴 관리**: A9, A10, A11, A12 (병렬 가능, 고객과 분리)
