# PART 1: 고객 기능 (Customer User Stories)

## Group 1️⃣: 고객 인증 (Table Authentication & Session)

### Story C1: 테이블 태블릿 자동 로그인

**ID**: C1  
**Persona**: 고객 (첫 방문 또는 재방문)  
**우선순위**: P0 (Critical)  
**복잡도**: M (Medium, 2-5일)  
**마이그레이션**: Sprint 1

**설명**:
테이블 태블릿이 처음 켜지면, localStorage에 저장된 테이블 인증정보(테이블 ID, 세션 토큰)로 자동 로그인되어야 한다. 이미 로그인된 상태라면 메뉴 화면으로 바로 진입한다.

**As a** 고객  
**I want to** 태블릿을 켜면 자동으로 로그인되어 바로 메뉴를 볼 수 있게  
**So that** 로그인 절차 없이 빠르게 주문을 시작할 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 태블릿의 localStorage에 유효한 테이블 ID와 세션 토큰이 저장되어 있고
When: 고객이 태블릿의 애플리케이션을 시작하면
Then: 자동으로 인증되어 메뉴 화면이 즉시 표시되어야 한다.

Given: localStorage에 저장된 세션 토큰이 만료된 경우
When: 고객이 태블릿의 애플리케이션을 시작하면
Then: 만료 오류를 감지하고 초기 설정 화면으로 리다이렉트되어야 한다.

Given: 처음 사용하는 태블릿이어서 localStorage에 아무 데이터가 없는 경우
When: 고객이 애플리케이션을 시작하면
Then: 초기 설정 화면이 표시되고 테이블 번호 입력을 요청해야 한다.
```

**상세 기준**:
- ✅ 로그인 소요 시간 < 1초
- ✅ 세션 타입: 테이블 태블릿 전용 (사용자 계정 없음)
- ✅ localStorage 구조 명확 (테이블 ID, 토큰, 만료 시간)

### Story C2: 테이블 초기 설정 (관리자로부터 받은 정보로 로그인)

**ID**: C2  
**Persona**: 고객 (첫 방문)  
**우선순위**: P0 (Critical)  
**복잡도**: M (2-5일)  
**마이그레이션**: Sprint 1

**설명**:
테이블 태블릿이 처음 사용될 때, 관리자로부터 받은 테이블 번호와 비밀번호를 입력하여 로그인한다. 로그인 성공 시 localStorage에 세션 토큰을 저장하고 메뉴 화면으로 진입한다.

**As a** 고객 (첫 방문)  
**I want to** 관리자로부터 받은 테이블 번호와 비밀번호로 로그인할 수 있게  
**So that** 내 테이블로 접속하여 주문할 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 테이블 태블릿의 localStorage가 비어있어 초기 설정 화면이 표시되고
When: 고객이 테이블 번호와 비밀번호를 정확히 입력하고 "로그인" 버튼을 누르면
Then: 서버 인증 성공 후 localhost에 세션 토큰이 저장되고, 메뉴 화면으로 자동 리다이렉트되어야 한다.

Given: 고객이 테이블 번호와 비밀번호를 잘못 입력했을 때
When: "로그인" 버튼을 누르면
Then: 명확한 오류 메시지 ("테이블 번호 또는 비밀번호가 잘못되었습니다")가 표시되고, 입력 필드는 초기화되어야 한다.

Given: 네트워크 연결이 불안정할 때 로그인을 시도할 때
When: 서버 응답이 없으면
Then: 3초 후 자동 재시도하고, 3회 실패 후 오류 메시지와 "다시 시도" 버튼을 표시해야 한다.
```

**상세 기준**:
- ✅ 비밀번호 최소 길이: 4자리 (관리자 설정)
- ✅ 입력 필드 대소문자 구분 없음
- ✅ 로그인 버튼: 큰 크기 (최소 50px 높이)

## Group 2️⃣: 메뉴 탐색 (Menu Browse)

### Story C3: 메뉴 리스트 조회 (카테고리별)

**ID**: C3  
**Persona**: 고객  
**우선순위**: P0 (Critical)  
**복잡도**: M (2-5일)  
**마이그레이션**: Sprint 1

**설명**:
고객이 로그인 후 메뉴 화면에서 모든 카테고리의 메뉴를 볼 수 있다. 각 메뉴는 사진, 이름, 가격, 간단한 설명이 표시된다.

**As a** 고객  
**I want to** 카테고리별로 메뉴를 구분해서 볼 수 있게  
**So that** 원하는 음식을 빠르게 찾을 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 고객이 메뉴 화면에 접속했을 때
When: 페이지가 로드되면
Then: 모든 카테고리(예: 음료, 에피타이저, 메인, 디저트)가 탭 또는 버튼으로 표시되고, 각 카테고리별 메뉴 리스트가 순차적으로 표시되어야 한다.

Given: 특정 카테고리를 선택했을 때
When: 해당 카테고리 탭을 누르면
Then: 화면이 그 카테고리의 메뉴로 스크롤 이동하거나, 해당 메뉴만 표시되어야 한다.

Given: 각 메뉴 항목이 표시될 때
When: 메뉴 화면이 로드되면
Then: 각 메뉴는 [이미지] [메뉴명] [가격] [간단 설명] 순서로 표시되어야 한다.
```

**상세 기준**:
- ✅ 메뉴 로드 시간 < 2초 (이미지 포함)
- ✅ 이미지 최적화: 모바일 해상도 (최대 300x300px 표시)
- ✅ 최소 텍스트 크기: 14px (가독성)
- ✅ 이미지 없음 시 기본 아이콘 표시

### Story C4: 메뉴 상세 정보 조회

**ID**: C4  
**Persona**: 고객 (신중한 고객)  
**우선순위**: P1 (High)  
**복잡도**: S (Small, 1-2일)  
**마이그레이션**: Sprint 1

**설명**:
고객이 특정 메뉴를 누르면 상세 정보(재료, 알레르기 정보, 칼로리 등)를 볼 수 있다. 모달 또는 상세 페이지에서 확인한 후 "추가" 버튼으로 장바구니에 추가할 수 있다.

**As a** 고객 (신중한 고객)  
**I want to** 메뉴의 상세 정보를 확인한 후 주문할 수 있게  
**So that** 알레르기나 불호 재료를 피해 안전하게 주문할 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 고객이 메뉴 리스트에서 특정 메뉴를 누를 때
When: 메뉴를 클릭하면
Then: 메뉴 상세 모달/페이지가 열려 다음 정보를 표시해야 한다:
  - 큰 이미지
  - 메뉴명, 가격
  - 상세 설명 (재료, 알레르기, 칼로리)
  - "추가" 버튼, "닫기" 버튼

Given: 고객이 상세 정보 보기를 닫고 싶을 때
When: "닫기" 버튼 또는 X 버튼을 누르면
Then: 모달이 닫히고 메뉴 리스트로 돌아와야 한다.
```

**상세 기준**:
- ✅ 모달 표시 애니메이션 < 200ms
- ✅ 정보 표시 순서: 이미지 → 기본정보 → 상세 설명
- ✅ 알레르기 정보는 붉은 색으로 강조

### Story C5: 메뉴 검색 (선택)

**ID**: C5  
**Persona**: 고객 (기술에 능한 고객)  
**우선순위**: P2 (Low)  
**복잡도**: S (1-2일)  
**마이그레이션**: Sprint 2

**설명**:
고객이 메뉴 리스트 상단의 검색창에 메뉴명을 입력하면, 실시간으로 필터링된 메뉴 리스트를 볼 수 있다. (MVP 후 추가 고려)

**As a** 고객 (기술에 능한 고객)  
**I want to** 메뉴 이름으로 검색할 수 있게  
**So that** 원하는 메뉴를 빠르게 찾을 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 메뉴 화면 상단에 검색창이 표시되고
When: 고객이 메뉴명을 입력하면
Then: 실시간으로 입력 텍스트와 일치하는 메뉴만 필터링되어 표시되어야 한다.

Given: 검색 결과가 없을 때
When: 고객이 존재하지 않는 메뉴명을 입력하면
Then: "검색 결과 없음" 메시지를 표시해야 한다.

Given: 고객이 검색을 취소하고 싶을 때
When: 검색창을 지우거나 X 버튼을 누르면
Then: 모든 메뉴 리스트로 돌아와야 한다.
```

**상세 기준**:
- ✅ 검색 반응 시간 < 300ms
- ✅ 대소문자 구분 없음
- ✅ 부분 일치 지원 (예: "스파" → "스파게티" 검색됨)

## Group 3️⃣: 주문 (Order)

### Story C6: 장바구니에 메뉴 추가

**ID**: C6  
**Persona**: 고객  
**우선순위**: P0 (Critical)  
**복잡도**: M (2-5일)  
**마이그레이션**: Sprint 1

**설명**:
고객이 메뉴를 선택하고 "추가" 버튼을 누르면, 메뉴가 장바구니에 추가된다. 수량을 지정할 수 있고, 총 금액이 실시간으로 업데이트된다.

**As a** 고객  
**I want to** 메뉴를 선택하여 장바구니에 추가할 수 있게  
**So that** 주문할 음식들을 준비할 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 고객이 메뉴 상세 보기에서 메뉴를 보고 있고
When: "추가" 버튼을 누르면
Then: 해당 메뉴가 장바구니에 추가되고 (수량 1), 성공 메시지가 표시되어야 한다.

Given: 같은 메뉴를 여러 번 추가할 때
When: 같은 메뉴의 "추가" 버튼을 다시 누르면
Then: 수량이 증가해야 하고, 중복 항목을 만들지 않아야 한다.

Given: 장바구니가 비어있다가 첫 메뉴를 추가할 때
When: "추가" 버튼을 누르면
Then: 장바구니 아이콘에 배지로 개수 (1)가 표시되어야 한다.

Given: 메뉴 추가 중 네트워크 오류가 발생할 때
When: 서버 요청이 실패하면
Then: 사용자에게 오류를 알리고 "다시 시도" 옵션을 제공해야 한다.
```

**상세 기준**:
- ✅ 메뉴 추가 시간 < 500ms
- ✅ 장바구니 업데이트는 localStorage에 자동 저장
- ✅ 수량 범위: 1~99

### Story C7: 장바구니에서 메뉴 수량 조절

**ID**: C7  
**Persona**: 고객  
**우선순위**: P1 (High)  
**복잡도**: S (1-2일)  
**마이그레이션**: Sprint 1

**설명**:
고객이 장바구니를 열어 각 메뉴의 수량을 증가/감소시킬 수 있다. 수량이 0이 되면 자동으로 장바구니에서 삭제되고, 총 금액이 실시간으로 업데이트된다.

**As a** 고객  
**I want to** 장바구니에서 메뉴의 수량을 조절할 수 있게  
**So that** 정확한 주문량을 준비할 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 고객이 장바구니를 열었을 때
When: 장바구니 페이지/모달이 표시되면
Then: 각 메뉴에 수량을 조절할 수 있는 +/- 버튼이 표시되어야 한다.

Given: 고객이 + 버튼을 눌러 수량을 증가시킬 때
When: + 버튼을 누르면
Then: 수량이 1 증가하고, 총 금액이 즉시 업데이트되어야 한다.

Given: 고객이 - 버튼을 눌러 수량을 감소시킬 때
When: 수량이 1인 상태에서 - 버튼을 누르면
Then: 수량이 0이 되어 해당 메뉴가 자동으로 장바구니에서 삭제되어야 한다.

Given: 장바구니가 비어있을 때
When: 모든 메뉴를 제거하면
Then: "장바구니가 비어있습니다" 메시지가 표시되어야 한다.
```

**상세 기준**:
- ✅ 수량 조절 반응 시간 < 300ms
- ✅ 총 금액 업데이트는 즉시 (라이브)
- ✅ localStorage에 즉시 저장

### Story C8: 장바구니에서 메뉴 제거

**ID**: C8  
**Persona**: 고객  
**우선순위**: P1 (High)  
**복잡도**: S (1-2일)  
**마이그레이션**: Sprint 1

**설명**:
고객이 장바구니에서 특정 메뉴를 삭제할 수 있다. 수량이 0이 되거나 삭제 버튼을 누르면 해당 메뉴가 장바구니에서 제거된다.

**As a** 고객  
**I want to** 장바구니에서 원하지 않는 메뉴를 제거할 수 있게  
**So that** 주문 실수를 바로잡을 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 고객이 장바구니에서 특정 메뉴를 제거하고 싶을 때
When: 메뉴 옆의 X 또는 "제거" 버튼을 누르면
Then: 해당 메뉴가 즉시 장바구니에서 삭제되고, 총 금액이 업데이트되어야 한다.

Given: 장바구니의 마지막 메뉴를 제거할 때
When: 마지막 메뉴를 삭제하면
Then: 장바구니가 비어있고 "장바구니가 비어있습니다" 메시지가 표시되어야 한다.
```

**상세 기준**:
- ✅ 제거 버튼: 명확한 위치 (각 메뉴 오른쪽)
- ✅ 확인 팝업: 불필요 (빠른 제거)
- ✅ localStorage에 즉시 반영

### Story C9: 주문 전 장바구니 내용 최종 확인

**ID**: C9  
**Persona**: 고객  
**우선순위**: P0 (Critical)  
**복잡도**: M (2-5일)  
**마이그레이션**: Sprint 1

**설명**:
고객이 주문을 생성하기 전에 최종 확인 화면을 본다. 모든 메뉴, 수량, 총 금액이 명확히 표시되고, "주문하기" 또는 "취소" 버튼이 있다.

**As a** 고객  
**I want to** 주문 전에 모든 항목과 총 금액을 최종 확인할 수 있게  
**So that** 주문 실수를 완전히 방지할 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 고객이 장바구니에서 "주문하기" 버튼을 눌렀을 때
When: 주문 확인 화면이 열리면
Then: 다음 정보가 명확히 표시되어야 한다:

When: "돌아가기" 버튼을 누르면
Then: 장바구니로 돌아가 수정할 수 있어야 한다.
```

**상세 기준**:
- ✅ 확인 화면 오픈 시간 < 500ms

### Story C10: 주문 생성 (주문 확정)

When: 첫 시도가 실패하면
Then: 3초 후 자동으로 재시도하고 (최대 3회), 모든 시도가 실패하면:

### Story C11: 현재 세션 주문 내역 조회

When: 관리자가 상태를 변경하면
Then: SSE를 통해 실시간으로 고객의 주문 내역이 자동으로 업데이트되어야 한다. (< 2초)

When: 주문 내역 페이지가 표시되면

- ✅ 이전 세션 주문은 제외

# PART 2: 관리자 기능 (Admin User Stories)

## Group 4️⃣: 관리자 인증 (Admin Authentication & Session)

### Story A1: 관리자 로그인

**ID**: A1  
**Persona**: 관리자  
**우선순위**: P0 (Critical)  
**복잡도**: M (2-5일)  
**마이그레이션**: Sprint 1

**설명**:
관리자가 매장 ID, 사용자명, 비밀번호를 입력하여 로그인한다. 로그인 성공 시 JWT 토큰이 발급되고 16시간 유효하다. 이후 자동 로그인 시 토큰으로 검증하며, 16시간 후 자동 로그아웃된다.

**As an** 관리자  
**I want to** 매장 ID와 사용자명, 비밀번호로 로그인할 수 있게  
**So that** 내 매장의 주문을 관리할 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 관리자가 로그인 화면에 있고
When: 정확한 매장 ID, 사용자명, 비밀번호를 입력하고 "로그인" 버튼을 누르면
Then: 로그인이 성공하고 JWT 토큰이 발급되어 localStorage에 저장되어야 한다.

Given: 관리자가 올바르지 않은 자격증명을 입력했을 때
When: "로그인" 버튼을 누르면
Then: 명확한 오류 메시지 ("매장 ID, 사용자명, 또는 비밀번호가 잘못되었습니다")가 표시되어야 한다.

Given: 관리자가 로그인한 후 16시간이 경과했을 때
When: 시간이 경과하면
Then: JWT 토큰이 만료되고, 자동으로 로그인 화면으로 리다이렉트되어야 한다.

Given: 브라우저를 새로고침했을 때
When: 관리자가 페이지를 새로고침하면
Then: localStorage의 JWT 토큰으로 자동으로 검증되어, 로그인 상태가 유지되어야 한다.
```

**상세 기준**:
- ✅ JWT 토큰 유효기간: 16시간
- ✅ 비밀번호: bcrypt 해싱 (서버)
- ✅ 로그인 소요 시간 < 1초
- ✅ 토큰 갱신: 로그인 시점마다 새로 발급

## Group 5️⃣: 실시간 주문 모니터링 (Real-Time Order Monitoring)

### Story A2: 실시간 주문 대시보드 (테이블별 카드)

관리자가 로그인 후 대시보드를 보면, 모든 테이블의 현재 주문 상황이 테이블별 카드 형태의 그리드로 표시된다. 각 카드는 테이블 번호, 총 주문액, 최신 주문 n개를 표시하고, SSE로 실시간 업데이트된다. (< 2초)

**As an** 관리자  
**I want to** 모든 테이블의 현재 주문 상황을 한눈에 볼 수 있게  
**So that** 어느 테이블이 주문을 했는지 빠르게 감지할 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 관리자가 대시보드에 접속했을 때
When: 대시보드 페이지가 로드되면
Then: 모든 테이블의 카드가 그리드 형태로 표시되어야 한다.

Given: 각 테이블 카드가 표시될 때
When: 대시보드가 로드되면
Then: 각 카드는 다음 정보를 포함해야 한다:
  - 테이블 번호 (크게, 명확하게) [배경색으로 구분 가능]
  - 테이블의 총 주문액 (예: 45,000원)
  - 최신 주문 3개 미리보기 (예: 라떼 x2, 케이크 x1, ...)
  - "상세 보기" 클릭 영역

Given: 새로운 주문이 들어올 때 (고객이 주문 생성)
When: 신규 주문이 서버에 저장되면
Then: SSE를 통해 해당 테이블 카드가 실시간으로 업데이트되어야 한다. (< 2초)

Given: 신규 주문이 표시될 때
When: 새 주문이 추가되면
Then: 해당 테이블 카드가 애니메이션(색상 강조 또는 깜빡임)으로 강조되어야 한다.

Given: 주문 상태가 변경될 때
When: 한 주문의 상태가 "대기중" → "준비중"으로 변경되면
Then: 해당 테이블 카드가 자동으로 업데이트되어야 한다.

Given: 네트워크 연결이 끊긴 상태에서 (오프라인)
When: 관리자가 대시보드를 계속 사용할 때
Then: 마지막으로 수신한 로컬 주문 데이터로 대시보드가 계속 동작해야 하고,
      "오프라인" 상태 표시가 나타나야 한다. (요구사항 4.2)

Given: 네트워크가 복구되었을 때
When: 연결이 재개되면
Then: SSE 재연결 후 그동안의 주문/상태 변경사항이 자동으로 동기화되어야 한다.
```

**상세 기준**:
- ✅ 카드 그리드: 반응형 (테블릿 화면)
- ✅ 카드 크기: 최소 120x150px
- ✅ SSE 업데이트 지연: < 2초
- ✅ 신규 주문 카드 강조: 노란 배경 또는 흰색 테두리 3초
- ✅ 오프라인 동작: 로컬 데이터 캐싱, 재연결 시 자동 동기화 (요구사항 4.2)

관리자가 메뉴의 "삭제" 버튼을 누르면 확인 팝업이 표시된다. 확인 후 메뉴가 삭제되고, 해당 메뉴를 포함한 주문들은 영향을 받지 않는다. (과거 이력 유지)

**As an** 관리자  
**I want to** 더 이상 제공하지 않는 메뉴를 삭제할 수 있게  
**So that** 메뉴 리스트를 정리할 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 관리자가 메뉴의 "삭제" 버튼을 눌렀을 때
When: 버튼을 클릭하면
Then: 확인 팝업 ("이 메뉴를 정말 삭제하시겠습니까?")이 표시되고,
      "삭제" / "취소" 버튼이 제공되어야 한다.

Given: 관리자가 "삭제"를 확인했을 때
When: 버튼을 클릭하면
Then: 메뉴가 삭제되고 성공 메시지가 표시되어야 한다.

Given: 삭제된 메뉴가 포함된 주문이 있을 때
When: 메뉴가 삭제되면
Then: 과거 주문 이력에는 영향을 주지 않아야 한다. (메뉴명은 유지됨)
```

**상세 기준**:
- ✅ 삭제 전 확인 팝업 필수
- ✅ 과거 주문 데이터: 삭제 메뉴도 조회 가능 (참조 무결성)
- ✅ 삭제 로그: 누가, 언제, 어떤 메뉴를 삭제했는지 기록

### Story A13: 메뉴 노출 순서 조정

**ID**: A13  
**Persona**: 관리자  
**우선순위**: P2 (Low)  
**복잡도**: M (2-5일)  
**마이그레이션**: Sprint 2

**설명**:
관리자가 메뉴의 노출 순서를 조정할 수 있다. 드래그앤드롭 또는 순서 번호 입력으로 카테고리 내 메뉴 표시 순서를 변경하며, 변경된 순서는 고객 메뉴 화면(C3)에 반영된다. (요구사항 3.2.4)

**As an** 관리자  
**I want to** 메뉴의 노출 순서를 조정할 수 있게  
**So that** 인기 메뉴나 추천 메뉴를 상단에 배치할 수 있다.

**Acceptance Criteria**:
```gherkin
Given: 관리자가 메뉴 관리 화면에서 특정 카테고리의 메뉴들을 보고 있을 때
When: 메뉴를 드래그앤드롭하거나 순서 번호를 변경하면
Then: 해당 카테고리 내 메뉴의 노출 순서가 즉시 변경되고 저장되어야 한다.

Given: 관리자가 메뉴 순서를 변경했을 때
When: 순서 변경이 저장되면
Then: 고객의 메뉴 화면(C3)에 변경된 순서가 반영되어야 한다.

Given: 순서 변경 중 오류가 발생했을 때
When: 서버 요청이 실패하면
Then: 이전 순서로 롤백되고 오류 메시지가 표시되어야 한다.
```

**상세 기준**:
- ✅ 순서 조정 방식: 드래그앤드롭 또는 순서 번호 입력
- ✅ 순서 저장: 카테고리별 정렬 순서 (display_order 필드)
- ✅ 변경 즉시 고객 화면 반영
