# User Personas - 테이블오더 서비스

**작성일**: 2026-08-31  
**버전**: 1.0  
**상태**: Active

---

## 개요

테이블오더 서비스의 두 가지 주요 사용자 유형을 정의합니다. 각 Persona는 실제 사용자 행동, 동기, 페인 포인트를 기반으로 작성되었습니다.

---

## 1. 고객 Persona: "다양한 배경의 테이블 사용자"

### 1.1 프로필

**이름**: 최종 고객 (Multiple Segments)

**역할**: 식당 테이블에서 주문하는 손님

**연령대**: 10세~80세 (전 연령대)

**기술 수준**: 초보자 ~ 기술에 능함 (다양)

**모바일/태블릿 경험**: 
- 초보자: 기본적인 터치 입력만 가능
- 일반: 스마트폰 사용 경험 있음
- 고급: 태블릿 앱 사용 경험 많음

---

### 1.2 세부 Segment

#### Segment A: 직관적 UI를 선호하는 일반 고객
- **특징**: 기술에 익숙하지 않음, 빠른 주문을 원함
- **기술 수준**: 초보자 (30%)
- **주요 행동**: 큰 버튼, 명확한 메뉴, 간단한 조작
- **Pain Point**: 복잡한 UI, 오류 메시지 이해 어려움

#### Segment B: 스마트폰 경험이 있는 일반인
- **특징**: 스마트폰은 능숙하지만 새로운 인터페이스는 학습 필요
- **기술 수준**: 일반 (50%)
- **주요 행동**: 사진, 가격, 직관적인 결과 중심
- **Pain Point**: 메뉴 설명 부족, 예상 시간 정보 부족

#### Segment C: 기술에 능한 사용자
- **특징**: 새로운 기술 빠르게 학습, 고급 기능 활용
- **기술 수준**: 기술에 능함 (20%)
- **주요 행동**: 빠른 탐색, 고급 필터, 자동화 기능
- **Pain Point**: 제한된 기능, 커스터마이징 불가

---

### 1.3 고객의 목표

#### 주요 목표 (Primary Goals)
1. **빠르고 편한 주문**: 최소 클릭, 최소 시간으로 원하는 음식 선택
2. **명확한 정보**: 메뉴 설명, 가격, 준비 시간 등 필요한 정보 한눈에 파악
3. **신뢰**: 잘못된 주문 걱정 없이 확신 있는 선택
4. **주문 추적**: 현재 주문 상태 실시간 확인

#### 보조 목표 (Secondary Goals)
5. **예산 관리**: 총 금액 확인, 숨겨진 비용 없음
6. **재방문 유도**: 편한 경험으로 다시 방문하고 싶은 마음

---

### 1.4 Pain Points (페인 포인트)

| 페인 포인트 | 설명 | 영향도 |
|-----------|------|--------|
| **직관적이지 않은 UI** | 버튼이 어디 있는지, 다음 단계가 뭔지 불명확 | 높음 |
| **메뉴 정보 부족** | 설명이 없거나 불충분하면 선택이 어려움 | 높음 |
| **이미지 로딩 지연** | 모바일 환경에서 느린 로딩으로 답답함 | 중간 |
| **오류 메시지 불명확** | 뭔가 잘못됐는데 왜인지 모름 | 중간 |
| **주문 상태 정보 부족** | 언제 준비될지 몰라 불안함 | 높음 |
| **페이지 새로고침 후 데이터 손실** | 장바구니가 초기화되는 불편함 | 중간 |

---

### 1.5 Frustrations (불만 포인트)

- "왜 이렇게 복잡하지? 음식만 시키려는데..."
- "사진은 왜 안 보이고 글자만 있어?"
- "내 주문이 어디까지 왔는지 모르겠어..."
- "실수로 누르면 다시 처음부터 해야 하나?"
- "아, 또 선택을 다시 해야 하네..."

---

### 1.6 주요 Use Cases

1. **첫 방문 고객**: 메뉴 탐색 → 선택 → 주문
2. **재방문 고객**: 빠른 주문 (습숙한 메뉴)
3. **단체 손님**: 여러 명이 동시에 주문, 순서대로 주문
4. **신중한 고객**: 충분한 정보로 최고의 선택 결정
5. **서두르는 고객**: 빠른 주문, 상태 확인

---

### 1.7 How to Measure Success

- ✅ 첫 주문까지 걸린 시간 < 2분
- ✅ 주문 실패 비율 < 5%
- ✅ 고객 오류로 인한 재주문 < 3%
- ✅ 주문 상태 업데이트 지연 < 2초
- ✅ 이미지 로드 시간 < 1.5초

## 2. 관리자 Persona: "효율적인 주방/홀 관리자"

### 2.1 프로필

**이름**: 매장 관리자 (한 명 또는 여러 명)

**역할**: 테이블오더 시스템 운영, 주문 관리, 메뉴 관리

**연령대**: 20세~60세 (주로 25~50세)

**기술 수준**: 평균 (일반)

**경험**:
- 기존 POS 시스템 사용 경험 있음
- 스마트폰/태블릿 기본 사용 능숙
- 새로운 시스템에 빠르게 적응 가능

---

### 2.2 업무 특성

#### 주요 업무
- **실시간 주문 모니터링**: 매 순간 새로운 주문 확인
- **주문 상태 관리**: 대기 → 준비중 → 완료 진행
- **테이블 관리**: 테이블 초기 설정, 세션 관료, 이력 관리
- **메뉴 관리**: 메뉴 등록/수정/삭제

#### 업무 시간
- **영업 시간**: 점심 (11시~14시), 저녁 (17시~22시)
- **비영업 시간**: 메뉴 관리, 과거 이력 정산

#### 동시 작업
- 1명: 최소 10-20개 테이블 관리
- 여러 명: 각자 역할 분담 (주방/홀)

---

### 2.3 관리자의 목표

#### 주요 목표 (Primary Goals)
1. **효율적 주문 관리**: 누락 없이 모든 주문 처리
2. **빠른 응대**: 신규 주문을 즉시 감지하고 처리
3. **실수 최소화**: 잘못된 주문 삭제, 중복 없음
4. **매장 효율성**: 테이블 회전율 최대화 (세션 종료)
5. **인건비 절감**: 최소 인력으로 최대 효율

#### 보조 목표 (Secondary Goals)
6. **데이터 기반 운영**: 과거 이력으로 패턴 파악 (피크 시간, 인기 메뉴)
7. **메뉴 최적화**: 메뉴 관리로 고객 수요에 빠르게 반응
8. **신뢰성**: 시스템 다운 시에도 계속 운영 가능

---

### 2.4 Pain Points (페인 포인트)

| 페인 포인트 | 설명 | 영향도 |
|-----------|------|--------|
| **실시간 알림 지연** | 주문이 들어오는데 알림이 늦으면 손님 불만 증가 | 높음 |
| **UI 찾기 어려움** | 급할 때 버튼을 못 찾으면 업무 지연 | 높음 |
| **오프라인 대응 불가** | 인터넷 끊기면 주문을 못 받아 손실 | 높음 |
| **복잡한 메뉴 관리** | 메뉴 변경이 많은데 관리가 어려우면 시간 낭비 | 중간 |
| **과거 이력 조회 어려움** | 정산할 때 정보를 못 찾으면 불신 | 중간 |
| **주문 삭제 확인 절차** | 실수로 삭제되면 큰 문제, 하지만 매번 확인은 번거로움 | 중간 |

---

### 2.5 Frustrations (불만 포인트)

- "주문이 들어오는 걸 못 봤어... 손님이 화낸다."
- "어? 이 버튼이 어디 있지? 급한데..."
- "와이파이가 끊겼다... 이제 어떻게 해?"
- "메뉴를 이렇게 많이 수정해야 해? 너무 번거롭네..."
- "어제 정산하려는데 기록이 없네?"

---

### 2.6 주요 Use Cases

1. **영업 시작**: 테이블 초기 설정, 메뉴 확인
2. **실시간 모니터링**: 신규 주문 감지, 상태 변경
3. **주문 처리**: 주문 삭제 (오류), 상태 진행
4. **테이블 종료**: 이용 완료 후 세션 종료, 정산 준비
5. **이력 조회**: 당일/기간별 과거 주문 정산
6. **메뉴 관리**: 메뉴 수정, 숨기기, 순서 변경 (필요시)
7. **오프라인 대응**: 인터넷 끊김 후 복구되면 자동 동기화

---

### 2.7 How to Measure Success

- ✅ 신규 주문 감지 시간 < 2초
- ✅ UI 작업 시간 < 5초 (상태 변경, 삭제 등)
- ✅ 오프라인 상황에서 로컬 데이터 유지율 100%
- ✅ 관리자의 오류 재작업 < 2%
- ✅ 메뉴 수정 소요 시간 < 1분

## 4. Design Implications (설계에 미치는 영향)

### 고객용 UI/UX
- 🎯 **명확성 우선**: 모든 텍스트, 버튼, 아이콘 직관적이어야 함
- 📱 **모바일 최적화**: 큰 터치 영역, 빠른 로딩
- 🖼 **시각적 정보**: 텍스트보다 이미지와 아이콘 활용
- 🔄 **안전한 데이터 유지**: localStorage, 재시도 로직
- ⚡ **빠른 응답**: 2초 이내 피드백

### 관리자용 UI/UX
- ⚡ **실시간성 우선**: SSE, 2초 이내 업데이트
- 🎯 **효율성**: 최소 클릭, 최대 정보 (대시보드)
- 🛡 **안전장치**: 삭제 확인, 오프라인 감지
- 📊 **정보 가독성**: 테이블 카드, 명확한 상태 표시
- 🔌 **오프라인 지원**: 로컬 데이터 캐싱, 자동 동기화
